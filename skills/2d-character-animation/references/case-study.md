# 《到点下班》骨骼动画复盘

来源：项目真实用户反馈、最终实现与验收记录（整理于 2026-09-25）。以下是重新撰写的方法总结；不公开原项目源码、人物美术、私有仓库链接或会话日志。旧方案曾包含串行登梯、统一黑色配件等要求，下表以最终有效修复为准。

| 症状 | 定位 / 根因 | 已采用的解决方法 | 防止再犯 |
| --- | --- | --- | --- |
| 立绘 creepy；先太胖，后全部同体型 | 写实脸与拼装感冲突；把“不要肥胖”解释成统一瘦身 | 扁平卡通统一风格，保留高矮、肩宽、轻微胖瘦差异 | 原尺寸头像 + 无颜色剪影 + 全身对比，先确认代表角色 |
| 老员工像老人 | 年资被错误编码为高龄 | 中年脸、地中海、黑框透明镜片与保温杯 | 单独检查年龄和职责辨识，不以职业名替代美术要求 |
| 人物左右手全反 | 画面左右与角色自身左右混用，镜像修复叠加 | 保留旧 screen 命名，显式映射 anatomical side | 正面标注“画面左=人物右”，检查拇指和持物关系 |
| 经理走路像后退 | 躯干/衣襟方向、位移和步态不一致 | 衣服单独镜像；重新统一步态方向与接触脚 | 面向、root 位移、脚尖/落脚点三箭头同时检查 |
| 同手同脚或两只手一起甩 | 摆臂直接依赖各脚绝对偏移 | 依据左右脚相对分离量做对侧摆臂，持物手限制幅度 | 看相对 pelvis 的手脚方向，检查最终渲染而非仅角度值 |
| 脚滑、膝反折、运动不符合生理 | root tween 与固定循环脱节，关节分支不稳定 | 落脚规划、接触锁地、双骨 IK、停步收势 | 完整接触期 world-space 足点漂移；镜像与极值角检查 |
| 老员工肘膝粗细不对齐 | 素材端宽、轴线与 joint pivot 不匹配 | 校准近远端坐标、匹配宽度、重叠连接 | 不用大圆遮缝；逐段检查极值、肤色和轮廓 |
| 财务乃至全员上下半身断裂 | 小裤头只覆盖中心；身体图重复臀部；腿根分离 | 骨盆按双腿 socket 宽度贴合，剪除重复臀部，桥接随动 | 躯干倾斜与大跨步都不能露洞或叠出第二套裤子 |
| 经理前臂落在衣服后，手穿胸 | DOM 骨骼层级限制 slot；动作路径穿过身体 | 世界骨矩阵与平面绘制顺序分离，伸手先绕躯干外侧 | 静态、扶额、前伸和交叉时分别查看路径与图层 |
| 老板持包肘向反方向弯 | 不同动作采用相反 IK/角度分支 | 统一与行走一致的屈曲分支，重新设计持包扇风动作 | 走路→生气连续采样，不能只查最终姿势 |
| 公文包中间透明 | 实体区域 alpha/遮罩异常 | 修复实体填充，保留真正把手开孔 | 亮/暗/棋盘背景与物体内部 alpha 检查 |
| 全黑道具看不清 | 色彩简化丢失材质与形状层级 | 保留上衣分组色；杯/电脑银色，网线/报表白色，钥匙金属色等 | 色彩编码服务识别，手与道具不要合成黑团 |
| 保温杯、电脑拿法别扭 | 道具围绕中心旋转，未按握持/托举点绑定 | 杯采用确认的竖握；打开电脑在底座掌心处绑定并保持水平 | 手/物握持点世界距离，躯干转动时也检查 |
| 阿姨指向、IT 耳机关系不自然 | 手型或道具 attachment 与动作语义不符 | 专用指向手型连接腕部；耳机归头部跟随 | 换手型不移动腕关节，检查戴物与头部遮挡 |
| 只有跺脚，生气看不出来 | 身体在动，脸没变；人人同模板 | 角色特有喜剧动作 + 夸张眉眼嘴形 + 💢 | 表情在小尺寸可读，峰值、停顿、余韵均可辨 |
| 所有人同一帧生气 | 没有独立触发延时 | 满员后队列先前移，按稳定 seed 错时反应 | 多端相同事件时序一致；不是每帧随机抖坐标 |
| 人走进梯时缩小消失 | 用 scale/opacity 代替空间进入 | 真实通道、共同尺度/地面、门框裁切、人物留在轿厢 | 每帧累计 scale/opacity 与实体身份；最高角色过门槛 |
| 开始前闪一下、像 PPT | 准备帧先显示结算结果，角色重建，切动作复位 | 旧场景持续保留，同一 rig 连续运动，从当前 pose 混合 | 采样交接前后帧与节点，不只比较开头结尾 |
| 上梯后下一天排队人突然变了 | 新快照立即替换旧人物 | 成功后关门 + 简短遮盖，再切到最新一天 | 请求失败保留旧场景；快照覆盖不回放历史 |
| 谁出了牌看不清 | 当前 actor 已提前推进，组色被误当操作者 | 公共行动记录驱动玩家高亮、飞牌、走入和日志 | 跨组出牌、快照合并、抽牌隐私与日志顺序 |
| 三人集合前还演插队，会议室头像提前出现 | 替代业务分支仍复用普通插队演出 | 先招呼集合再同行；阿姨先叫回；进入后才显示单个收集头像 | 同一三人 rig、收集者归属、路径连续和出现时机 |
| 严重卡顿，浏览器表现不同 | WebKit 的逐骨整图染色滤镜；Chromium 的 React 重建与中间结果帧 | 离线小片 WebP、共享贴图、静态 memo、变化骨骼更新、批量布局 | 真实满场/并行负载、卡帧指标与 idle 写入预算 |
| 首帧只有关节圆点 | 图片异步解码尚未完成，连接图形先显示 | 完整附件 ready 后一次显露角色绘图层，保留布局 | 冷缓存、失败、重连、批量角色首次显示 |
| 房间进度导致动画重渲染 | 缓存 ready 计数订阅在场景父级 | 房间级资源 session，只有进度条订阅变化 | 0→100 时场景 render 计数稳定；完成常驻 100% |
| 刷新/后台重播旧动作或角色再次起步 | 遗留 timer/回调及缺少事件消费位置 | 稳定序号、取消延迟任务、直接重建最终姿态 | 跳过/断线/隐藏中途恢复，不补播错过效果 |

## 性能事实的适用范围

最终实际使用的角色资源集约 221 个文件、2.05 MiB；此前某次烘焙总集约 249 个文件，二者不是同一清单。离线裁切和共享无色部件是方法，文件数不是新项目目标。

一轮桌面 Chromium/WebKit、375×812、33 人、30 秒采样，记录约 9.3/9.2ms 的 p95、25.7/24.9ms 最大帧间隔，超过 50ms 的帧为 0。该数据不是实体 iPhone 性能证明，也不能复制到其他设备报告。案例保留了更早的严重卡顿门槛，但它不是“稳定 60fps”的定义。

缓存实测覆盖冷加载、同会话开局不重复请求及刷新后持久缓存命中；未证明系统永不驱逐缓存、真实弱网或长期温控表现。

## 从失败中提炼的工作顺序

先约定角色/屏幕左右与坐标 → 确认原稿轮廓 → 校准接缝与握持 → 使骨骼和绘制层独立 → 落脚与 root 联动 → 保留实体和姿态连续 → 在真 UI 中编排 → 满场测性能 → 再考虑等待期预加载/缓存。

这是一条减少返工的依赖顺序，不是要求每次小修都重走全流程。旧动画已正确时，改一只手只验受影响动作和相关回归即可。
