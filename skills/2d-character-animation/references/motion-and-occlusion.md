# 步态、运动逻辑与遮挡

## “在后退”从三个方向排查

1. root 路径的世界运动方向。
2. 脸、躯干、衣襟和脚尖所表达的朝向。
3. 接触脚在局部空间移动的方向、摆腿落点与手臂相位。

只翻转人物贴图不能解决根运动和接触脚相反；只反转时间轴也可能把摆腿变为倒放。

## 行走不是两条腿作正弦摆动

区分接触、承重、离地、前摆、落地。普通走路至少有一只脚支撑；承重脚在世界坐标中的位置近似不动，root 向前时该脚在 root 局部向后。摆腿在前进方向落脚，脚底抬离地面，脚尖与踝部收束。

有限距离移动先规划落脚点，再由 root 的路径、速度与 easing 驱动骨骼。步数/步幅应随距离调整，临停最后两步收拢到站姿；不能用固定周期 walk 配任意速度 root。路径发生转弯时按路径切线和弧长处理，不把 screen-X 当成全程前进轴。

双骨 IK 的输入需转到同一局部坐标空间。长度为 a、b 时，距离限制在可达区间，余弦输入限制到 [-1,1]，并持续选择同一肘/膝分支。再加符合该角色、视角和动作的关节范围；不把项目里某个角度符号当作全局生理规定。

正常步态中同侧手臂与腿的前后分量相反，等价于手臂与对侧腿配合。用左右脚的相对分离量建立摆臂，而不是分别拿相对 root 的绝对偏移驱动——后一种写法可能让双手同时向一边甩。拿物品的手可以小幅摆动或保持水平，另一只手补偿；不要求所有角色完全对称。

验收时看 1× 整体节奏和 0.25× 接触帧；用世界坐标测脚滑动。不要用动画自己生成的“计划脚点”作为唯一真值，还要测最终骨骼/脚底的实际投影。

## 遮挡与变换解耦

骨骼树表示“谁带着谁移动”，绘制顺序表示“谁盖住谁”，DOM 父子顺序不应把两件事绑死。可以计算世界骨矩阵后按独立 slot 顺序画，或使用 runtime 的 draw-order timeline。

静态 near/far 顺序只是起点。跨躯干、扶额、指向、持物和经过门框时重新检查遮挡。前臂可以在胸前，肩膀仍保持合理连接；道具可以在掌心前、手指后。手应沿身体外侧的可读路径绕到脸前，不能穿过胸口再靠 z-index 把穿模藏掉。

视角没有变化时，不要每帧按手的 X 坐标交换前后层。必要切层选在合理的交叉位置，并检查前后邻帧；换 slot 时不换骨骼世界坐标。镜像版本必须重复检查。

## 场景移动与空间连续

排队、电梯和临时房间共享人物尺度、地面与门槛。门洞确实容得下最高角色；紧凑场景优先缩小间距、错位站立并允许肩部遮挡。后排可略抬站位，但不能用任意缩小冒充进入深度。

角色实际走过门槛再由门框/边界遮住。进入后留在场内；别以淡出或缩小代替行走。需要换容器时，用容器世界矩阵的逆将现有世界姿态换算到新局部坐标；一帧只保留一个实体。优先让同一渲染节点完成整段路径和最终停留。

## 喜剧与生气

用“发生了什么 → 角色看懂 → 做出反应 → 留下情绪”的节奏。结合身份/道具给每个角色一个主要笑点：扇包降温、扶额、抱紧电脑、碎碎念、指向堵住的路等；不套同一个跺脚模板。

表情与肢体有清楚的峰值；眉眼、嘴形先表达情绪，💢 放大、弹出、轻颤和停留只做强化。说话与回应可错拍，不让所有人同一帧一起抖。

随机感用稳定 seed（事件序号 + 角色 ID）推导启动延时，各端可复现。延时是触发时刻的微差，不是每帧随机改骨骼坐标。触发条件按业务叙事明确：本案例最终是三梯并行登梯，满员后剩余队列依原顺序前移，再错时生气；最终保留生气状态。

持续生气不等于永久循环大幅跺脚。保留表情和可读停姿，必要时轻微待机；刷新可以直接生成同一最终姿态。其他产品若需要消气，应使用其自己的状态设计。
