# 前置约定与最小样片

## 先查现状

从项目文件、已有图像、用户确认和实际运行画面获取信息。能查到的不要重新问。缺少会改变做法的信息时，只问关键项，同时继续独立工作。

| 需要确定 | 为什么 | 应保存的结果 |
| --- | --- | --- |
| 目标平台、runtime、实际人物像素高度、DPR | 决定切片尺寸、场景负载和采样方式 | 目标设备与素材预算 |
| 素材来源、许可、可编辑原稿、已确认造型 | 避免未经授权重画或混入 runtime | source → calibration → bake → runtime 路径 |
| 参考视角、解剖左右、屏幕左右、镜像策略 | 避免“左右全反”后反复修补 | 一张标注双手、拇指、脚尖和持物手的图 |
| 原点、X/Y 方向、单位、角度零向与正向 | 避免跨工具旋转方向相反 | `rig-contract.json` |
| 肩/肘/腕、髋/膝/踝中心与接缝宽度 | 保证分段合拢且弯曲可信 | 原图像素标定 + parent-local joints |
| 站立地面、场景门洞、通道与角色尺度 | 避免靠缩小人物塞进场景 | 门槛和脚底的共同坐标基准 |
| 必须表达的动作、目标对象、最终状态 | 区分位移、互动、转场和角色循环 | action → path → pose → result |
| 当前性能基线与用户审核边界 | 避免带着错误基础批量制作 | 可重复测试场景与一段审核样片 |

模板不是另一套必须迁移到的新引擎。已有 schema 足够时写适配导出，不改变卡牌 ID、业务归属或存档格式来配合美术。

## 素材最低条件

- 原图透明边缘完整，手、脚、道具不被画布切掉；关节后面被遮住的部分要补全。
- 附件保留原始画布位置、裁切 offset 和 pivot。换图时不能默默改变这些坐标。
- 不把颜色、头型、体型和角色职责绑成一维：分组颜色是一层，角色轮廓与道具是另一层。
- 手与道具至少能控制握持点；需要握紧、托住或指向时，准备匹配的手型附件，而不是把错误手型旋转硬凑。
- 先用中性背景和实际像素尺寸看静态拼装，再看大图细节。写实脸与扁平拼接肢体混用，容易产生恐怖谷观感。

## 先选一名“难而有代表性”的角色

优先选择持物、长四肢、衣袖不对称或有脸部遮挡的角色。样片要覆盖：自然站立、两次完整步态、前伸、肘最大屈曲、持物转向、表情峰值和收势。无持物角色先做好不能证明持物角色也可复用。

将角色放到真实队列、门洞和小屏布局里；单独展示的人物没有页面重排、密集遮挡和并行动画压力。样片通过后再批量补齐角色和服色。

本案例的七角色、五组色、银色电脑、黑色裤子等都是项目美术决定。其他项目只复用“先确认可辨识性、用有限变量编码身份”的方法。
