# 验收与防回归

## 三种证据不能互相替代

1. **数据检查**：坐标、长度、引用、状态和帧统计的确定性约束。
2. **视觉检查**：人体方向、手型、透视、接缝、遮挡、笑点与动作质感。
3. **运行检查**：目标场景、真实交互、网络时序、浏览器与设备负载。

“脚计划不漂移”不证明渲染脚底不漂移；“节点存在”不证明没有被裁掉；“两端截图正常”不证明中途没有闪帧。

## 人物检查矩阵

| 场景 | 必看 |
| --- | --- |
| 七角色/项目全部角色静立、剪影、头像 | 高矮体型差异、年龄、可辨识脸和道具 |
| 全部组色与动作极值 | 袖子接缝、肤色、材质边界、黑色衣物是否吞掉手/道具 |
| 正反朝向、伸手、持物、扶额、指向 | 解剖左右、拇指、手背/手掌、肘膝分支、前后层 |
| walk 接触/离地/摆腿/落地/停止 | 锁脚、对侧配合、髋重心、最后一步收势 |
| 躯干侧倾与最大跨步 | 腰胯/腿根覆盖、有没有第二套臀部轮廓 |
| 表情开始/峰值/保留/退出 | 眉眼嘴形、镜片、💢 锚点、说话与接话 |
| 原尺寸与放大图，亮/暗/棋盘格背景 | Alpha 破洞、接缝、图像边缘与实际可读性 |

暂停于极值与交接帧，并查看前后相邻帧。1× 录屏用于看连贯性；0.25× 用于定位，不能只交慢放样片。

## 场景与状态矩阵

- 队列空/满/超长、空梯/未满/满员/溢出、最高/最矮角色、同色与混色重叠。
- 正常排队、插队、叫回、群体同行、最后一张牌、并行登梯和持续停留。
- 验证 root 的屏幕路径、同一节点身份、累计 scale/opacity、门槛裁切；只查局部 transform 会漏掉父容器缩放。
- 成功、失败、重复点击、重复快照、一个快照包含多个事件、快速新状态、后台、断线、刷新、中途 resize；如果提供 skip，也测 skip 后没有延迟角色重新启动。
- 下一阶段确认前仍显示当前画面；确认后转场期间不提前暴露新场景；完成时显示最新快照。
- 320/375px、横屏、桌面、非零 safe area、放大文字、所有语言；实际拖放、横滑、弹层内滚动与焦点。用项目支持的尺寸调整这些案例值。

## 自动检查器的数据约定

`audit.py rig` 接收[结构示例](../assets/rig-contract.example.json)：

- `coordinate_system` 明确解剖左右、原点、坐标单位、Y 方向与角度正向；示例为屏幕 Y 向下、顺时针正角、骨骼零向为 +Y。
- `bones` 为 parent-local 层级；`anatomical_side` 与 `screen_side_at_rest` 分开。样例检查正/背面、单次镜像的左右映射；三分之四/侧面保留显式值并要求目视校对。
- `attachments` 的 `proximal_px/distal_px` 是切片内像素，`scale` 是源像素到骨骼单位的等比倍率；骨长和两个端点的实际距离应一致。
- `draw_order` 覆盖附件且无重复。该检查只能确认声明完整，不能判断前臂是否应该在胸前。

`audit.py trace` 接收[轨迹示例](../assets/motion-trace.example.json)：

- `samples` 是同一不间断测量段的实测帧；时间单位 ms，坐标统一 CSS 屏幕像素。后台/暂停分段采样，不把人为暂停当成卡帧。
- 每个 actor 有稳定 `id`、运行时实体 `node`、累计 scale/opacity、root 屏幕坐标、可选 feet/grips/joints 与最终骨矩阵。
- 每个锁定接触期使用稳定 `contact` token。只有整个接触期不换 token，检查器才能发现渐进滑步；不要每帧生成一个新 token 让断言失效。
- `grips` 是手上握持点与道具握持点最终投影的成对位置。`joints` 可包含实测角度、允许区间、`bend_sign`；区间由已审核角色填写，不能从想要通过的输出反推。
- `rigid_matrices` 检查归一化后的刚性世界矩阵：两列长度各为 1、相互垂直、行列式绝对值为 1。仅检查 determinant=1 会漏掉 (2, 0.5) 这样的非等比伸缩。
- `required_actors` 声明整段持续存在的人物；仅为真实存在的采样范围填写，否则正常入场也会误报。需要交接时优先保留同一 node。
- budget 全部显式配置：脚滑、握持漂移、位移速度、关节角速度、scale/opacity 变化与帧时长。示例值是故障演示参数，不能当成默认产品验收阈值。

```bash
python scripts/audit.py rig path/to/exported-rig.json
python scripts/audit.py trace path/to/recorded-trace.json
```

输出 JSON：`ok`、`errors`、`metrics`。约束失败退出 1，输入/格式错误退出 2，通过退出 0。脚本不访问网络、不运行浏览器、不修改素材。

缺少脚、握持、角度等可选数据时在 `coverage` 里列为未覆盖。即使脚本返回通过，也只能说明已提供指标满足预算，不能宣称整个人体、遮挡和帧间视觉已验收。

## 从真实渲染取得数据

使用项目的开发验收页或 runtime 的调试导出能力，在同一帧渲染后采样。不要把动画输入值再当成输出证据。

- DOM/SVG：用稳定实体引用（例如 WeakMap 分配 token）记录 `node`；将真实脚底/握持 landmark 经最终屏幕变换投影。只读取 `transform` 字符串会漏掉父层、滚动和 viewBox。
- Canvas/WebGL：记录当前渲染实体与最终 world→screen 矩阵，再把相同 landmark 投影到 CSS 像素，不能混入 framebuffer 像素。
- `scale` 是相对已审核人物尺度的正倍率，标准为 [1,1]；`opacity` 包含父层累计影响。意图中的镜像单独记录，不把 -1 当成缩小。
- `rigid_matrices` 先除去已批准的静态美术标定比例，只有应当刚性的骨骼才进入列表。明确批准的 squash/mesh 变形另做视觉和几何检查，不伪造单位矩阵让测试通过。
- 同时保存真实画面。数值看起来连续，但贴图替换、裁切和颜色错误仍可能造成闪帧。

## 留存验收结果

复制[验收报告模板](../assets/acceptance-report.md)，记录真实来源、设备、DPR、满场规模、刷新率、采样方式、对照版本、指标与证据位置。分别列出通过、失败和未实测项。不要把案例原来的测量数字填成新项目结果。

## Skill 自身的行为回归场景

更新本 skill 时用这些任务检验决策质量；它们是待执行场景，不是自动测试已经完成的证据。

| 用户请求 | 应有决策 | 不可接受的捷径 |
| --- | --- | --- |
| “经理右手在衣服后面，先只修这个” | 查清角色右/屏幕左、当前视角、slot 与手臂路径，局部修改 | 整个骨架和所有动作左右互换 |
| “单个人流畅，满场卡成 PPT” | 在满场测量滤镜、绘制、解码、重渲染与布局成本 | 只加 easing，或缩小人物、删动效后称通过 |
| “给新人电脑换成打开的” | 保持已审核骨长和比例，修道具/手型、握持 anchor 与遮挡 | 重生成所有角色并丢失原比例 |
| “全部人物同手同脚” | 对照 root 方向和实际脚点，检查对侧关系及持物例外 | 按名字简单反转一个 sin，忽略父镜像和足部接触 |
| “先给我看动画，认可再集成” | 完成可审核连续样片，等用户审核后才集成；其余独立工作继续 | 一直问空泛确认，或未审核就发布 |
| “这组资源已经分层，不要换 runtime” | 直接校准现有附件，选择必要工具 | 强制重新生成立绘或安装 Spine |
