# 连续演出与多人状态

## 将真相、演出和布局分开

```text
server snapshot / ordered public events
          ↓                         ↘
  authoritative latest state       activity log
          ↓
  presentation queue → actors / paths / poses
          ↑
  measured scene geometry (batched)
```

业务状态决定谁行动、归属、目标和结果；演出只决定怎样展示。操作者不等于卡牌组别，更不等于已推进到下一回合的 actor。字幕、高亮、飞牌起点和日志都绑定正在播放的事件。

用稳定事件序号消费一个快照内的全部新事件，不只保存最后一次行动。重复快照不能重播；跳过、后台、重连直接重建最新稳定画面。只有在当前任务需要时改协议；已有可靠事件接口就复用。

## 从 PPT 到连续动作

- 角色 ID/React key 跨 walking、gathering、cabin、idle 保持稳定。
- 动作切换先捕获当前姿态，短暂混合到下一动作的入口；同时考虑角度最短弧和可见速度方向，避免关节绕一圈。
- root 路径与姿态使用一致的时间源和移动计划。不要渲染每个关键帧为独立图片，再用 setTimeout 串成动画。
- 完成回调把当前姿态作为终态交接，不先复位到 idle(0) 再绘制最后帧。
- 消除“先渲染结果，再挂载动画覆盖”的中间帧；演出开始前保留旧画面直到运动实体已经就绪。
- 手动 GSAP cleanup 要区分 kill（停止）和 revert（恢复原样）。卸载时可以按所有权还原，保留演员的动作交接则不要让旧 timeline 的 revert 把新姿态抹掉。使用唯一动作 token / generation，使过期回调无法再写节点。
- 确实需要 React GSAP 生命周期时使用现有 scoped context 或 useGSAP，外部监听器/计时器另行清理；工具分工见[来源说明](tool-routing.md)。

## 卡牌/群体行动

先服务器确认，再显示成功路径；失败恢复输入并保留原实体。飞卡 → 揭开 → 同尺寸人物 → 走到队列，是一个位置连续的交接链。

本案例三人聊八卦是一个替代分支：新人物招呼两人集合后同行，不先执行普通插队对白；阿姨先完成有效叫回。三人进入收集者的临时房间后才出现收集头像。公开抽牌只展示牌背/组色，不能为了动画暴露私有角色。

并行动画使用一条主时间轴加独立子序列；总完成时刻取最长分支，不是把三部梯顺序相加。并行会增加瞬时负载，必须在满场测试中验证。

## 下一阶段的遮盖与切换

下一天请求只提交一次。新快照确认成功后，暂时保留旧场景，关门 → 短遮盖 → 展示最新一天；排队角色在有叙事依据的遮盖中更新，避免直接消失。

关门期间保留最新快照，完成后直接显示最新状态，不能补播已被遮盖的历史动作。请求失败保持原画面并恢复重试。最后一天是否转场取决于产品规则，不自动套“下一天”。

不要对持久房间内容设置 opacity:0 来做阶段切换；被中断的 timeline 可能永远不恢复。使用专门转场覆盖层，并将弹窗放入视口级 portal，避免被角色 transform 的 stacking context 困住。

## 清理矩阵

| 事件 | 停止什么 | 显示什么 |
| --- | --- | --- |
| mute | 声音 source | 视觉继续，按产品约定 |
| skip（若提供） | 当前和延迟启动任务 | 最新完整静态结果 |
| background / disconnect | RAF、计时器、声音、待启动 callback | 恢复后直接同步当前状态 |
| resize | 失效几何路径 | 重新测量或无跳变接续；不重播旧行动 |
| leave / unmount | 该房间拥有的资源与监听器 | 不写已卸载节点 |
| request failure | 本次未确认演出 | 原局面和可用交互 |

自动完成、清理与跳过按钮是不同概念。用户删掉跳过按钮后，内部取消/最终态机制仍应保留。
